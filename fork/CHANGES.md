# Fork changes

Every change this fork carries on top of upstream, one line each:
commit subject, why, and related upstream issues and PRs.
`git log --no-merges upstream-main..main` lists the commits, including
follow-ups and reverts. Include issue links even when no PR exists yet; a related
issue may cover more than the fork's fix. Keep each entry on a single line;
the sync script deletes the line of a change whose upstream PR merged. Closing
an issue alone does not revert a patch. See `fork/README.md` for how to add or drop
an entry.

- `fix(web): show the result of the notified delegated task`: completion cards select the task IDs carried by their notification, so continuing a child conversation no longer makes later completions display the original task's interrupted result; legacy notifications keep their child-thread lookup. Issue: none linked. PR: https://github.com/pingdotgg/t3code/pull/22141

- `fix(server): Claude takes agent updates at tool boundaries`: agent updates to a busy Claude turn wait in the durable queue (the upstream PR's rule) and the running turn takes them at its next root PostToolBatch or Stop hook, with no timer; unclaimed updates start the next turn. Held queues and stopped runs refuse the claim, so Stop wins. Updates with attachments steer natively with a note that they came from another agent. Human steering, explicit restarts and other providers are unchanged. Offered upstream on top of the maintainer's takeover. Issue: https://github.com/pingdotgg/t3code/issues/21895. Related PR: https://github.com/pingdotgg/t3code/pull/21158
- `feat(server): support time zones for fixed-time scheduled tasks`: agents can set an IANA time zone such as UTC for daily or weekday schedules, or clear it with null; omission preserves an existing zone on update and uses server-local time on creation. Web/mobile show and preserve configured zones, including saves from older clients. Fork-only. Issue: none linked. PR: none yet

- `feat(claude): allow proxy-held requests up to an hour`: Claude Code defaults to a one-hour API timeout so quota-router stall pins can hold a request for 59 minutes; explicit environment overrides remain in effect. Fork-only. Issue: none linked. PR: none yet
- `feat(web): schedule tasks without a project`: scheduled tasks can run without picking a project. Squashes two commits by Sam Scott. Issue: none linked. PR: https://github.com/pingdotgg/t3code/pull/17257
- `fix(server): launch projectless scheduled tasks in scratch folders`: Scratch launches (including projectless scheduled tasks) always get a per-thread folder, even with a saved worktree strategy, and retries reuse the folder the first create claimed. Pairs with PR 17257. Issue: none linked. PR: none yet
- `fix(mcp): return delegated task handles before client timeouts`: blocking delegation waits return a task handle before MCP clients time out (30 s default, 45 s cap). By maria-rcks. Issue: https://github.com/pingdotgg/t3code/issues/11168. PR: https://github.com/pingdotgg/t3code/pull/15622
- `fix(server): skip unsupported native Codex usage reads`: custom providers and API-key accounts no longer call `account/rateLimits/read`, which fails for them and marked usage as broken. Issue: none linked. PR: none yet
- `fix(server): retain Claude reset times across usage-limit retries`: retries on the same conversation and model keep valid reset metadata when Claude omits it, so automatic recovery remains available. Issue: none linked. PR: https://github.com/pingdotgg/t3code/pull/15110 (closed, unmerged)
- `fix(server): a handoff too large for the context window no longer wedges the thread`: an oversized context handoff is marked deferred so the user's turn proceeds, and later turns on the same provider thread retry it until it fits. Issue: https://github.com/pingdotgg/t3code/issues/16147. PR: https://github.com/pingdotgg/t3code/pull/19414 (replaces #16244 and #18620)
- `fix(server): tell agents to link outside files by absolute path`: shared runtime guidance, including Pi's system prompt, tells agents to use absolute Markdown targets for files outside the workspace. Issue: https://github.com/pingdotgg/t3code/issues/10553. PR: https://github.com/pingdotgg/t3code/pull/18370 (closed pending maintainer direction)
- `fix(server): detect Windows npm provider binaries for updates`: Codex instances configured with npm's native executable can update through T3, and manual-only installs no longer suggest an unavailable update action. Issue: none linked. PR: none yet
- `feat(web): download files from chat file links`: the context menu on chat file links offers "Download file" for any host file the connection can read, including files outside the workspace, so remote clients can fetch agent output. Issue: none linked. PR: none yet
- `fix(fork): show release deltas and link fork notes`: release notes list upstream changes and only new or updated fork patches since the previous published build, even after rebases; desktop release links follow the configured updater repository. Issue: none linked. PR: none yet
- `feat(server): skip cache writes on cold Claude compaction`: opt-in Claude setting **Skip cache writes on cold compaction** runs a compaction of a thread idle 70+ minutes, whose Claude process was already released, without prompt caching, so the history the summary replaces is not cached again; the next message reopens Claude with caching (one extra process start). Saves usage only if every gateway or proxy forwards requests without cache markers unchanged; the compaction sends `X-CPA-Prompt-Cache-Mode: explicit` for a CLIProxyAPI build that honors it. Issue: https://github.com/pingdotgg/t3code/discussions/18069 (was https://github.com/pingdotgg/t3code/issues/18067). PR: none yet
- `feat(server): retry Codex turns that fail on model capacity`: when Codex fails a turn with "Selected model is at capacity" (`serverOverloaded`, no Retry-After), the run stays open and continues with empty-input turns for one hour of waiting, starting at 10s and doubling up to a 3-minute cap across 24 retries; the retry row counts down and Stop cancels it. When the failed turn's subagents are still running, the retry waits for them to finish, and Stop in the meantime ends them and settles the run. Issue: https://github.com/pingdotgg/t3code/issues/12826 (closed). PR: none yet
- `feat(claude): suggest the next prompt as composer ghost text`: opt-in Claude setting shows Claude's predicted next prompt in the empty composer (Right Arrow or Tab accepts it, Esc dismisses it). Squash of danielyc's PR, adapted to the fork's settings and docs. Issue: none linked. PR: https://github.com/pingdotgg/t3code/pull/17618
- `feat(codex): predict the next prompt as composer ghost text`: opt-in Codex setting **Composer predictions** asks ChatGPT's composer prediction service for the next prompt after each completed turn and shows it through the same ghost text; needs ChatGPT sign-in, and whether it counts against usage is unverified. Builds on PR 17618. Issue: none linked. PR: none yet
- `fix(server): switching providers no longer revokes the other provider's T3 tool access`: MCP credentials are kept per thread and provider instance, so a provider session still attached after a switch keeps a valid token scoped to itself. Issues: https://github.com/pingdotgg/t3code/issues/16565 and https://github.com/pingdotgg/t3code/issues/18852. PR: https://github.com/pingdotgg/t3code/pull/19413 (replaces #18884)
- `test(web): include fork prompt suggestion settings in provider fields`: provider settings tests include the intentional Codex and Claude prompt-suggestion fields, keeping the fork release checks in step with their schemas. Issue: none linked. PR: none yet
- `fix(server): one silent provider no longer stalls every thread`: effects that outlive their worker lease release capacity for other conversations, and provider acceptance requests have deadlines. By Lakshmi Tanmay, adapted to the fork. Issue: https://github.com/pingdotgg/t3code/issues/16636. PR: https://github.com/pingdotgg/t3code/pull/16790
- `fix(server): wait for effect settlement when draining workers`: draining remains a completion milestone even after an effect's worker lease expires. Issue: https://github.com/pingdotgg/t3code/issues/16636. PR: none yet
- `fix(server): preserve ownership of delayed Codex starts`: delayed starts and compactions retain their request ownership through rejection or native completion, so retries cannot adopt or interrupt another turn. Issue: https://github.com/pingdotgg/t3code/issues/16636. PR: none yet
- `fix(server): persist run failures after storage recovers`: ingestion failure terminal writes retry typed errors and defects through the existing ownership gate, ending on service shutdown instead of leaving runs permanently working after a transient storage failure. Issue: none linked. PR: https://github.com/pingdotgg/t3code/pull/19646
- `fix(web): allow Working threads as chat references`: Working section (beta) threads can be dragged into another chat's composer while remaining fixed in their automatic sidebar section. By Nikita Maximilian Grimm. Issue: https://github.com/pingdotgg/t3code/issues/16137. PR: https://github.com/pingdotgg/t3code/pull/15269
- `fix(server): queued messages land after a resume that ran before them`: a queued message that starts after a resume, reorder, or automatic wake (such as a delegated task completing) takes the next run ordinal, so the transcript, checkpoints, and forks follow the order runs actually ran in. Squash of Lakshmi Tanmay's PR. Issue: https://github.com/pingdotgg/t3code/issues/16987 (closed after the client half). PR: https://github.com/pingdotgg/t3code/pull/17773 (competing draft https://github.com/pingdotgg/t3code/pull/18094)

Sync merges upstream nightlies into `main` without rewriting fork commits, and reverts a merged PR's patch only once the selected upstream commit includes its merge commit. Fork-only.
- `fix(server): keep prompt suggestions with their current run`: late predictions and cleanup from a retained provider session cannot replace or clear the current run's suggestion after switching providers. Fork-only follow-up to the Claude and Codex suggestion features. Issue: none linked. PR: none yet
- `feat(client): fork conversations from completed compaction turns`: web, desktop, and mobile can fork from a completed compaction marker once its containing run settles; a fork from automatic compaction includes the rest of its turn. Native forks need an exact turn boundary: Claude `/compact` turns record their persisted command echo as that boundary, while Claude automatic compactions and markers recorded before this change stay unavailable. Related issue: https://github.com/pingdotgg/t3code/issues/17423 (Claude rollback across compaction, not this feature). PR: none yet
- `fix(server): Git status refresh no longer scans the working tree twice before auto-pull`: when auto-pull is on and the default branch is behind, a status refresh reuses the local status it just read for the clean-tree check instead of scanning again, and invalidates local status after the fetch so a snapshot cached during the fetch cannot authorize a pull. It also reconciles local status after a failed pull attempt and propagates failed recovery reads. The original trace spent 10.2s in the repeated scan; real-repository before/after timing remains unmeasured. Issue: https://github.com/pingdotgg/t3code/issues/19684. PR: https://github.com/pingdotgg/t3code/pull/19447 (closed without merge; retained in the fork).
- `feat(fork): version releases after their upstream nightly`: fork release versions are the upstream nightly they are built on plus `.fork` (upstream synced, nothing new) or `.fork.<n>` (nth release with new or updated fork patches on that nightly), and a release that would sort below the newest fork release fails instead of publishing. Patches upstream's nightly version checks (desktop update channel and label, desktop build feed, web Nightly label, CLI release channel) to accept the suffix. Server updates preserve fork versions for installed fork servers and desktop-managed servers; upstream servers and manual npm commands use the corresponding upstream version. Fork server updates do not wait for npm publication; CLI and mobile release checks, archive downloads, and SSH bootstrap use the fork repository for fork versions, preserving explicit download mirrors. Fork-only. Issue: none linked. PR: none yet
- `fix(desktop): updates keep the app's administrator level on Windows`: after an auto-update, the Windows installer starts T3 Code at the elevation it had before (admin stays admin, normal stays normal) instead of always relaunching non-elevated through electron-builder's `ExecShellAsUser`; if the updater must elevate the installer itself, the app comes back elevated. Issue: none linked. PR: none yet
- `fix(claude): a wake handled by a queued message no longer stalls the thread`: when a user turn runs a Claude background wake to its result, the wake's buffered frames are marked settled, so the still-queued continuation replays them and settles instead of waiting forever and rejecting later turns as "still active". Issue: none linked. PR: none yet
- `fix(server): preserve delegated question delivery across task lifecycle`: child questions use safe active steering when supported, and Stop, cancellation, and disposal suppress late notices and cancel queued ones; retains the fork's protections around upstream's question reactor from PR 19521. Issue: none linked. PR: none yet
