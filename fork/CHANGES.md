# Fork changes

Every change this fork carries on top of upstream, one line per feature or fix:
its original commit subject, why, and related upstream issues and PRs.
`git log --no-merges upstream-main..main` lists the commits, including
follow-ups and reverts. Follow-ups rewrite their change's line instead of
adding one; see _Adding a change_ in `fork/README.md` for the exception.
Include issue links even when no PR exists yet; a related issue may cover more
than the fork's fix. Keep each entry on a single line; the sync script deletes
the line of a change whose upstream PR merged. Closing an issue alone does not
revert a patch. See `fork/README.md` for how to add or drop an entry.

- `feat(claude): compact only idle threads that will resume`: **Compact idle threads** splits **Before the cache expires** into **waiting threads** and **all threads** (Smart; waiting is the default); waiting threads compacts a Claude thread only when a watched PR or issue, awaited subagent or background work, or a scheduled task aimed at it will wake it after its prompt cache expires. **Compact snoozed threads** (default on, shown when the global choice or any Claude provider override compacts before the cache expires; with only an override doing so, **Only compact waiting threads** shows as a switch) lets snoozed threads compact and counts the snooze end as a wake; any scheduled task or snooze ending before expiry skips compaction because the cache is still warm. The wire keeps the mode plus a separate `smartIdleCompaction` boolean, because shipped clients reject unknown idle compaction modes; the dropdown writes both, targets that differ in either show Mixed, servers without the boolean show the single **Before the cache expires** choice, and a provider override of **Before the cache expires** follows the global waiting/all choice. Threads get **Compact before cache expires** (follow settings, this time only, always, never) in web, desktop and mobile thread menus and through `t3_thread_configure`. **This time only** (`"once"`) stores `compactOnceRequestedAt` and compacts after the current turn if nobody replies before the cache expires, then returns to the thread's choice: it applies like **Always** in any mode but **Never** (including **When you return**) until any run starts after it, so nothing clears it; setting null, true or false removes it, a thread set to **Never** refuses it, and shells report it as `compactOnce` (older servers omit it and hide the choice). Agents are told to use it when ending a turn that waits on the user with a large context. `t3_thread_send` with `contextPolicy: "compact"` to the caller's own busy thread queues the compaction after the current turn instead of refusing. Compaction turns no longer claim queued agent messages at Claude hook boundaries, so reports start the next turn. Older servers hide the thread control. Opt-in **Skip cache writes on cold compaction** runs a compaction of a thread whose prompt cache has expired (by the TTL Claude reported for its latest turn; unknown keeps caching) and whose Claude process was already released, without prompt caching, so the history the summary replaces is not cached again; the next message reopens Claude with caching (one extra process start). It saves usage only if every gateway or proxy forwards requests without cache markers unchanged; the compaction sends `X-CPA-Prompt-Cache-Mode: explicit` for a CLIProxyAPI build that honors it. Issue: https://github.com/pingdotgg/t3code/discussions/18069 (cache writes; was https://github.com/pingdotgg/t3code/issues/18067). PR: none yet
